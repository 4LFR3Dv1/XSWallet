1. Objetivo

Este relatório mede o nível de conformidade entre o que está definido nos documentos HTML do projeto para integração frontend-backend e o comportamento implementado no código atual.

Importante: este relatório não usa os arquivos .md como base normativa, somente os HTMLs solicitados.

1.1 Legenda de status

  • Conforme - comportamento implementado compatível com o contrato descrito.
  • Parcial - parcialmente compatível; há gaps relevantes.
  • Não conforme - desvio direto do contrato/objetivo descrito.

2.1 Resumo quantitativo

  • Conforme: 2 itens
  • Parcial: 4 itens

Risco principal: divergência de comportamento entre caminho IPC e caminho HTTP para autenticação/sessão, com impacto direto em previsibilidade de runtime.

3. Ações Prioritárias

3.1 P0 (imediato)

  1. Fechar caminho padrão em IPC para operações críticas de wallet/swap/session.
  2. Manter HTTP somente sob flag de debug explícita, sem uso implícito em produção.
  3. Consolidar contrato de sessão único entre frontend, electron, bridge e core.

3.2 P1 (curto prazo)

  1. Unificar helper de transporte/erro para reduzir deriva de contrato.
  2. Cobrir com testes de paridade IPC vs HTTP (modo debug) para evitar regressão.

3.3 P2 (planejado)

  1. Fechar fluxo de restore de ponta a ponta, com contrato explícito de disponibilidade.
Conclusão executiva: a documentação HTML descreve claramente a direção IPC-first; o código já possui base sólida de hardening e IPC, mas ainda com lacunas relevantes de migração e paridade de contrato.
