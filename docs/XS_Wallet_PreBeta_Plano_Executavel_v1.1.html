2.2 Contrato de Sessão

  • unlock deve retornar session_id real e frontend/electron devem usar esse token.
  • Qualquer 401/Unauthenticated em chamada protegida => limpar sessão e redirecionar para /unlock.
  • lock invalida sessão no backend e limpa token local.

Teste rápido (manual)

# unlock válido
curl -X POST http://127.0.0.1:3000/api/v1/wallet/unlock \
  -H "Content-Type: application/json" \
  -H "authorization: Bearer dev" \
  -d '{"pin":"SEU_PIN"}'

# chamada protegida com token inválido (espera erro auth)
curl -sS http://127.0.0.1:3000/api/v1/swaps -H "authorization: Bearer invalid"

2.3 IPC Hardening

  • Whitelist de canais (já existente em electron/ipc/channels.ts) deve ser fonte única.
  • Todos os handlers mutáveis com validação + timeout + tratamento de erro sem sucesso fake.
  • Rate-limit para operações sensíveis (unlock/init/restore/send/swap.create).
