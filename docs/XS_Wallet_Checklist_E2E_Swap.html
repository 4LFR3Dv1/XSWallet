1. Objetivo e Critério de Pronto

1.1 Objetivo

Fechar o pipeline de swaps ponta a ponta com comportamento determinístico, idempotente e recuperável após crash, priorizando o fluxo Submarine como base antes da expansão para Reverse e Chain.

1.2 Definition of Done (DoD)

Critério Resultado esperado Status
Estados do swap Transições válidas, sem saltos inválidos, com CAS por versão Concluído (core)
Idempotência de commit/reconcile Reexecução não duplica broadcast nem side effects Parcial
Crash recovery Reinicio retoma swaps ativos sem corrupção de estado Concluído (baseline)
Pipeline E2E Submarine Teste canônico verde em regtest Pendente
Suite principal go test ./... verde Concluído

1.3 Invariantes de Encerramento (Obrigatórias)

ID Invariante Status atual
I1 Broadcast único por swap/lockup: para um swap_id, no máximo 1 operação broadcast_lockup efetivada (mesmo com retry/crash). Parcial
I2 Transição final única: completed/failed só pode ser atingido uma vez; reconciles repetidos não geram novos eventos finais. Parcial

2. Checklist por Componente

2.1 Swap Service (core/internal/server/swap_service.go)

  • Parcial Exigir expected_version em LockSwap e CommitSwap.
    Commit exige explicitamente; Lock usa versão recebida, mas sem validação explícita de ausência.
  • Concluído Mapear erro de concorrência para codes.Aborted.
  • Concluído Mapear transição inválida para codes.FailedPrecondition.
    Implementado em Commit e Lock.
  • Pendente Garantir persistência de dados de commit (ex.: lockup_txid) quando aplicável.
  • Concluído Garantir snapshot consistente após cada mutação.

2.2 Orquestrador Submarine (core/internal/swap/submarine.go)

  • Parcial Cobrir fluxo completo: CreateFromQuote → Lock → Commit.
    API existe, mas fluxo real ainda parcial no serviço principal.
  • Concluído Preencher locked_intent antes da transição para locked.
  • Concluído Usar idempotência antes de operações de efeito externo (broadcast/pagamento).
  • Concluído Retornar erro explícito e rastreável para falhas de provider/adapters.

2.3 Engine e Estado (core/internal/swap/engine.go)

  • Concluído Todas as transições válidas devem registrar evento em swap_events.
  • Concluído Incremento de version em toda mutação de estado.
  • Parcial Cobrir transições inválidas com testes negativos.
  • Concluído Garantir API de idempotência (swap_ops) para operações críticas.

2.4 Watcher/Reconcile (core/internal/watcher/watcher.go)

  • Concluído Reconcile de swaps ativos no boot e em ciclo periódico.
  • Parcial Avançar estado de forma determinística com base em evidência on-chain/provider.
    Hoje usa facts internos com status de provider simplificado.
  • Parcial Evitar transição duplicada para mesmo evento (idempotência).
    Dedupe por event_key implementado no reconcile; pendente ampliar evidências externas completas (provider/LN).
  • Concluído Logging operacional com swap_id, estado anterior e próximo.

3. Checklist de Testes

3.1 Unit e Integration

  • Concluído Teste de CommitSwap cobrindo: missing expected_version, stale version e fluxo válido.
  • Parcial Testes de transição inválida no engine.
  • Concluído Teste de idempotência (RecordOperation/CheckIdempotency).

3.2 E2E Canônico (core/test/e2e/submarine_test.go)

Parcial O teste atual cobre quote/create/lock e ainda não executa commit + confirmação + conclusão.

Asserts canônicos obrigatórios para fechar o pipeline:

  • A1 - swap_events monotônicos e sem transição inválida.
  • A2 - version monotônica e consistente com mutações.
  • A3 - rodar ReconcileAllActiveSwaps duas vezes e garantir no-op na segunda execução (sem eventos/operações novas).
  1. Criar quote com parâmetros válidos.
  2. Criar swap a partir do quote.
  3. Executar lock com controle de versão.
  4. Executar commit.
  5. Forçar confirmação em regtest (blocos).
  6. Executar reconcile.
  7. Validar estado final e invariantes (version, events, lockup_txid).

3.4 Blocker de Persistência de Commit

Blocker: persistência durável de dados de commit (ex.: lockup_txid e evidências associadas) no mesmo ponto de verdade do swap é requisito para reconcile confiável.

3.3 Crash Recovery (core/test/e2e/crash_recovery_test.go)

Concluído Cobertura funcional existente para retomada após crash e validação de idempotência.

  1. Interromper após commit_started.
  2. Reiniciar core/db/watcher.
  3. Rodar ReconcileAllActiveSwaps.
  4. Validar continuidade sem duplicidade de operação.
Nota operacional: testes E2E devem falhar por infraestrutura apenas quando bitcoind/elementsd não estiverem acessíveis. Erros de compilação devem ser tratados como regressão de código.
