Onboarding, unlock, rotas, camada API/IPC, build e testes de fluxo

1. Objetivo

Entregar um frontend que execute o fluxo completo de wallet sem gaps, sem telas sem saída e com comportamento consistente em Electron (IPC) e fallback HTTP.

Resultado esperado: usuário consegue criar carteira, confirmar mnemonic, desbloquear e navegar no app sem erros de integração.

2. Estado Atual (Resumo)

  • Core e bridge estão operacionais.
  • Fluxo principal existe com suporte a HTTP e caminho parcial via Electron/IPC.
  • Build do frontend está funcional; scripts do root do monorepo ainda estão em transição.
Risco: sem padronizar contratos de integração e cobertura de testes, regressões voltam rápido e bloqueiam entrega.

3. Requisitos Funcionais do Fluxo Completo

  1. Estado not_initialized: direcionar para onboarding.
  2. Criação de carteira: PIN informado pelo usuário (mínimo backend), criação via API, exibição do mnemonic.
  3. Confirmação de backup: validação de palavras e só então conclusão do setup.
  4. Unlock: usar PIN real, mostrar erro real do backend e tentativas restantes.
  5. Estado unlocked: entrar no dashboard, sem redirecionamento para unlock.
  6. Restore: implementar de verdade ou desabilitar explicitamente (sem dead-end).

4. Plano Técnico de Implementação

4.1 Base de build

  • Manter frontend com build de produção verde e sem regressão de tipos.
  • Separar claramente scripts de root e scripts de frontend/electron.
  • Validar com npm --prefix frontend run build.

4.2 Onboarding sem PIN hardcoded

  • Adicionar campos: PIN e confirmação no OnboardingWelcome.
  • Validar mínimo de 8 caracteres.
  • Enviar initVault(pin) com input do usuário.
  • Tratar erro de already exists redirecionando para /unlock.

4.3 Regras de roteamento consistentes

  • status === unlocked sempre vai para /.
  • status === locked vai para /unlock.
  • status === not_initialized vai para /onboarding.

4.4 Camada API/IPC padronizada

  • Criar helper único para transporte: tryIPCThenHTTP().
  • Padronizar parse de erro backend em todas as chamadas.
  • Aplicar o padrão em wallet, swaps, nodes e health.

4.5 Restore wallet

  • Se endpoint não existir: botão com rótulo "Indisponível nesta versão".
  • Se endpoint existir: implementar formulário de mnemonic + PIN.

5. Contrato de Estados (Frontend)

Estado do Vault Rota alvo Ação de UI
not_initialized /onboarding Exibir criação/restauração
locked / locked_out /unlock Exibir tela de PIN
unlocked / Exibir dashboard e rotas protegidas

6. Critérios de Aceite

  1. npm run build executa sem erro.
  2. Em estado inicial, app abre diretamente onboarding.
  3. Criação de wallet usa PIN do usuário e conclui setup.
  4. Unlock aceita o PIN criado e entra no dashboard.
  5. Mensagens de erro mostram causa real do backend.
  6. Sem loop entre /onboarding e /unlock.
  7. Fallback HTTP funciona quando IPC não está disponível.

9. Riscos e Mitigações

Risco 1: regressão de roteamento.
Mitigação: tabela de estados + testes de navegação por estado.
Risco 2: divergência IPC vs HTTP.
Mitigação: helper único de transporte e testes com IPC ligado/desligado.
Risco 3: erro genérico escondendo causa real.
Mitigação: parse padrão de erro backend em toda a API.
