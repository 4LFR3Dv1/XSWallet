Definition of Done Global

  • Logs com traceId em todas as operações críticas.
  • Erros normalizados: code, message, details, traceId.
  • Idempotência explícita em ações de lifecycle de node.
  • Estado locked bloqueia mutações sensíveis.
  • Streams com reconnect + dedup.

EPIC F0 — Foundations (2–3 dias)

Objetivo: amarrar contratos e criar o esqueleto Electron sem quebrar o fluxo atual.

Story: Contrato HTTP → IPC → gRPC (matriz)

Tarefas

  • Inventariar rotas HTTP atuais (método, path, payload, response, erros).
  • Mapear cada rota para channel IPC (nome + schema + auth requirement).
  • Mapear calls renderer-safe vs privileged.
  • Definir padrão único de erro.

Aceite (DoD)

  • Matriz: HTTP route → IPC channel → gRPC method.
  • Schemas versionados (contracts/v1/*).
  • Lista de canais proibidos no renderer.

Story: Estrutura Electron inicial

Tarefas

  • Criar electron/main.ts, electron/preload.ts, electron/ipc/.
  • Script npm run electron:dev com hot reload básico.
  • Garantir render da UI atual.

Aceite

  • App abre em dev.
  • window.xs exposto via preload (stub) sem quebrar build.

Inputs

  • Rotas atuais de api-bridge e uso em frontend/src/services/api.ts.

Outputs

  • Matriz de contratos + shell Electron inicial.

Kill criteria

  • Se build tooling consumir >1 dia sem app abrir, simplificar setup para mínimo viável.

EPIC F1 — Electron Shell Seguro (3–4 dias)

Objetivo: hardening + política de IPC com validação.

Story: Hardening de BrowserWindow

Tarefas

  • contextIsolation=true, sandbox=true, nodeIntegration=false.
  • enableRemoteModule=false.
  • CSP ativa (sem unsafe-eval em prod).
  • Restringir navegação e abertura de novas janelas.

Aceite

  • Renderer sem acesso a require, process, fs.
  • Links externos via shell.openExternal.

Story: IPC whitelisted + validação

Tarefas

  • Registry único de canais.
  • Validação de schema + rate limit mínimo para canais críticos.
  • Normalização de erro + logging com traceId.

Aceite

  • Canais fora da whitelist são bloqueados.
  • Payload inválido retorna erro padronizado.
  • Logs com channel, traceId, durationMs e resultado.
Guardrail: separar canais read-only vs mutating.

EPIC F2 — Migração Frontend HTTP → IPC (4–6 dias)

Objetivo: renderer fala apenas com window.xs.invoke.

Story: Refactor do client

Tarefas

  • Trocar frontend/src/services/api.ts para xsApi.ts.
  • Fallback HTTP apenas com DEBUG_HTTP=1.

Aceite

  • Onboarding, unlock, balances e swap básico via IPC.
  • api-bridge fora do caminho padrão.
  • Erros coerentes sem stack leak.

Story: Sessão e autenticação local

Tarefas

  • Definir prova de unlock no renderer.
  • Bloquear canais mutantes em estado locked.

Aceite

  • Operação crítica não executa quando locked.
  • Lock/unlock atualiza permissões imediatamente.

EPIC F3 — Node Manager Core (1–1.5 semana)

Objetivo: lifecycle real + observabilidade via core.

Story: Lifecycle start/stop/restart

Tarefas

  • Modelo NodeInstance (type, pid, dataDir, binaryPath, ports).
  • Start com checagem de portas e dataDir.
  • Stop graceful + kill fallback.
  • Restart idempotente.

Aceite

  • Start/stop/restart sem terminal.
  • Estado com pid/uptime/lastExit reflete realidade.

Story: Health checks + sync progress

Tarefas

  • Bitcoin/Elements via getblockchaininfo.
  • LND via GetInfo + sync + peers.
  • Mapear estados NORMAL/DEGRADED/OFFLINE/STARTING/STOPPING.

Story: WatchLogs (stream)

Tarefas

  • Captura stdout/stderr ou tail de arquivos.
  • Backpressure + truncation + limite de linhas.

EPIC F4 — Binários + Verificação (1 semana)

Objetivo: garantir supply-chain mínimo seguro.

Story: Manifest assinado

Tarefas

  • JSON canônico com version, os, arch, url, sha256, sigEd25519, createdAt.
  • Root public key embutida no app (rotacionável).

Aceite

  • Manifest/assinatura inválidos são recusados.
  • Logs explicam motivo sem vazar segredo.

Story: DownloadBinary + VerifyBinary + Install

Tarefas

  • Download com resume + hash streaming.
  • Install atômico: tmp → verify → move.
  • Permissões corretas de execução.
Guardrail: não confiar em hash no mesmo canal do binário sem assinatura.

EPIC F5 — Streams de Swap e Reconcile (4–5 dias)

Objetivo: swaps vivos + recovery pós-restart consistente.

Story: WatchSwap / WatchAllSwaps

Tarefas

  • Evento canônico: SwapObservedEvent { swapId, stage, evidence, timestamp }.
  • Dedup por eventId/hash.

Story: Recovery pós-restart

Tarefas

  • Rehidratar swaps pendentes do storage.
  • Reconciliar com fontes externas no boot.

EPIC F6 — UI Node Manager (3–4 dias)

Objetivo: operar nodes sem terminal, com guardrails.

Story: Tela status + ações

  • Cards por node: status, sync, peers, last error.
  • Start/stop/restart com confirmação.
  • Logs em stream.

Story: Guard rails

  • Matriz operação crítica → dependências mínimas.
  • Mensagens de bloqueio com ação corretiva.

EPIC F7 — Empacotamento Desktop (4–6 dias)

Objetivo: instalador + assinatura/notarização.

Story: electron-builder config

  • Targets mac/win/linux (prioridade definida).
  • Bundle de preload + assets.

Story: Code signing / notarização

  • Pipeline separado para assinatura.
  • Documentar prereqs e secrets handling.

EPIC F8 — Testes E2E Desktop (1 semana)

Objetivo: fluxos críticos cobertos + falhas típicas simuladas.

Story: E2E críticos

  • bootstrap nodes, vault/unlock, send BTC/Liquid, swap MVP, restart/recovery.

Story: Falhas

  • crash node durante operação, timeout RPC, binário inválido, reconexão de streams.

Contratos mínimos sugeridos (IPC)

  • wallet.getStatus
  • wallet.unlock
  • wallet.lock
  • wallet.getBalances
  • swap.create
  • swap.watchAll (stream)
  • nodes.list
  • nodes.start
  • nodes.stop
  • nodes.restart
  • nodes.watchLogs (stream)
  • binaries.ensureInstalled(nodeType, version?)
Regra: canais nodes.*, binaries.*, swap.create são privileged.

Dependências e caminho crítico

  • F1 é pré-requisito de F2 para evitar dívida de segurança.
  • F3 desbloqueia F6 e fundamenta F5 real.
  • F4 reduz risco reputacional/supply-chain antes de auto-instalar nodes em produção.
  • F8 depende de traceId + erro padronizado desde F1.

Ajustes Operacionais Recomendados

  • Em cada fase: registrar Inputs, Outputs e Kill criteria.
  • Manter o DoD global obrigatório em todos os tickets.
