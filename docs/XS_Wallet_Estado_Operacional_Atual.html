1. Leitura Executiva

O projeto atingiu um estado geral de operação integrada com cadeia crítica funcional entre interface, camada desktop e backend de carteira. O fluxo principal de wallet BTC (testnet) foi validado ponta a ponta com evidência real de controle on-chain: UTXO identificado, transação assinada pelo app, aceitação em mempool e confirmação em bloco.

Além do funcionamento operacional, houve avanço estrutural de arquitetura: IPC como caminho padrão para operações críticas, contrato de sessão consolidado entre camadas e mitigação para gargalos de descoberta de UTXO em nós pruned/testnet.

2. Estado Geral Atingido por Camada

2.1 Frontend (React/Vite)

  • Wallet Control Center operacional para endereços, UTXOs, reservas e histórico.
  • Serviços de API com contrato alinhado para IPC-first e fallback HTTP controlado.
  • Normalização de payload de saldo para evitar divergência entre transportes.

2.2 Electron (Main + IPC Registry)

  • Canal IPC consolidado para operações críticas de wallet/swap/session.
  • Validação de payload e controle de acesso por canal.
  • Tratamento explícito de sessão expirada em respostas UNAUTHENTICATED/401.

2.3 API Bridge

  • Contrato HTTP local estável para frontend/electron e tradução consistente para gRPC.
  • Respostas de unlock/status alinhadas com o fluxo real de sessão.
  • Observabilidade básica de requests com latência e códigos por endpoint.

2.4 Core (xscore / WalletService)

  • Derivação e persistência de endereços por chain em wallet_addresses.
  • Listagem de UTXOs com cache de scan e execução em background.
  • Fallbacks para reduzir impacto de timeout/lentidão de scantxoutset.
  • Fluxo de envio on-chain com seleção de UTXO, assinatura e broadcast.

5. O que já pode ser considerado concluído

  1. Integração funcional FE-BE no caminho oficial da aplicação desktop.
  2. Contrato de sessão operacional para unlock/status/chamadas protegidas.
  3. Wallet BTC testnet utilizável para operação on-chain real.
  4. Correção de pontos críticos de indisponibilidade por timeout no fluxo de UTXO.

6. O que está em consolidação (não regressão, mas maturação)

  • Performance determinística de scantxoutset em cenários com maior volume/endereços.
  • Redução adicional de dependência de scan global para inicialização de estado.
  • Fechamento completo dos gates de pré-beta em trilhas de swap/release/restore UI.

9. Próximo Estado-Alvo (continuidade natural)

  1. Encapsular estratégia de UTXO discovery para reduzir dependência de scans amplos no caminho crítico.
  2. Adicionar prova de controle por assinatura no app (sem gasto de UTXO) como ferramenta operacional.
  3. Concluir gates restantes de pré-beta (swap stream global, restore UX completo e release hardening).
