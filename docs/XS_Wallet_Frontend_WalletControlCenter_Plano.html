1. Objetivo

Adicionar uma página de Wallet Control Center que torne a carteira autossuficiente para operação real, suporte e auditoria básica pelo usuário, sem depender de CLI.

2. Problema atual

  • Fluxo de swaps avançado já existe, mas falta visão completa da carteira.
  • Usuário não visualiza claramente endereços derivados, UTXOs reservados e estado operacional completo.
  • Ausência de controles guiados para operações sensíveis (export de chave/backup).

4. Princípios de segurança

  • Regra fixa nunca expor private key em texto por padrão.
  • Qualquer export sensível exige vault desbloqueado + confirmação dupla + mensagem de risco explícita.
  • Log de auditoria interno para ações sensíveis (swap_events/wallet_events quando disponível).
  • Sem fallback silencioso para dados críticos: mostrar estado degradado quando backend não estiver pronto.
Export de private key/WIF deve ser feature flag desabilitada por padrão em builds de produção até revisão final de segurança.

5. Contrato de tela (estrutura)

  1. Resumo: saldo consolidado, health dos backends, último refresh.
  2. Addresses: BTC/Liquid/LN receive endpoints, derivation path, QR/copy, rotação.
  3. UTXOs & Reservations: tabela com valor, confirmações, reservado, swap_id.
  4. Security: backup status, xpub/zpub, export protegido.
  5. Activity: histórico wallet + correlação com swaps.

6. Plano por PR

PRStatusEntrega
PR1 Pendente Wallet Control skeleton + resumo + bloco de endereços derivados (BTC/Liquid)
PR2 Pendente Tabela de UTXOs/reservas e indicadores de lock por swap
PR3 Pendente Security center (backup/xpub/export protegido) com guard rails
PR4 Pendente Activity timeline + correlação tx/swaps + hardening UX final

PR1 - Base operacional

  • Nova tela WalletControlPage no frontend.
  • Cards de saldos BTC/Liquid/LN e estado de conectividade.
  • Painel de endereços com copy/QR e derivation path.

PR2 - UTXO/Reservation control

  • Tabela com colunas: chain, txid:vout, amount, confirmations, reserved, swap_id.
  • Incluir metadados de origem da reserva: reservation_type (lockup/fee/manual/unknown), reserved_at, reserved_by (swap_engine/manual/recovery) e expires_at (quando houver TTL).
  • Filtros por chain/estado reservado.
  • Destaque de UTXO indisponível por swap ativo.

PR3 - Security center

  • Checklist de backup exibindo status operacional.
  • Separar explicitamente “xpub view” de “export”: masked view padrão, reveal temporário opcional com timeout visual, copy como ação separada com confirmação, e export em fluxo próprio.
  • Exibição de xpub/zpub com aviso de privacidade e trilha de auditoria de ações sensíveis.
  • Export protegido por PIN + confirmação dupla + cooldown + guard rails reforçados.

PR4 - Activity e hardening final

  • Timeline de transações wallet com tipagem de evento (não apenas lista): event_type (RECEIVE/SEND/SWAP_LOCK/SWAP_CLAIM/REFUND/RESERVATION_SET/RESERVATION_RELEASE), status (pending/confirmed/failed/unknown), chain, txid, swap_id?, timestamp, evidence_level (observed/inferred).
  • Correlação com swaps quando houver lockup_txid/claim_txid/refund_txid.
  • Tratamento de estados degradados (RPC down, sync em andamento, vault locked).

8. Critérios de aceite

  1. Usuário consegue operar recebimento BTC/Liquid sem sair da UI.
  2. UTXOs reservados por swaps ficam claramente identificados.
  3. Nenhuma ação sensível ocorre sem confirmação explícita.
  4. Em falha de backend, UI mostra estado degradado com mensagem acionável (sem valores fake).
  5. Tela suporta debug operacional mínimo de wallet + swap correlation.
