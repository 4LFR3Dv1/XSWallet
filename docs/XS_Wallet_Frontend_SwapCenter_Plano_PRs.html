  • Timeline por swap já está disponível via /api/v1/swaps/:id/events e stream SSE.
  • Formulário já exige destination_address para reverse/chain e invoice para submarine.
  • Resumo operacional no create flow já mostra route/amount/destination para reduzir erro humano.
  • Pendência principal no frontend: hardening final de UX de produção (wizard/guard rails finais) e acabamento de mensagens.

1. Problema Atual

A tela de swap ainda não expõe todos os dados críticos para operação real. Hoje o usuário não consegue inferir com clareza:

  • de onde os fundos saem (funding source),
  • para onde o resultado final vai (destination),
  • quais passos precisam ser executados manualmente (funding/pagamento invoice),
  • quais riscos e timeouts estão em jogo.

2. Princípios de UX/Produto

  1. Todo swap precisa de destino explícito por tipo (kind).
  2. Antes do submit, usuário deve ver um “contrato” de swap legível.
  3. Após create, tela deve instruir o próximo passo operacional sem ambiguidade.
  4. Timeline e detalhes devem servir para suporte/debug sem depender de CLI.

PR1 - Inputs críticos obrigatórios

  • Objetivo: impedir criação de swap subespecificado.
  • Mudanças:
    • submarine: exigir Lightning Invoice (ou toggle explícito de invoice interna).
    • reverse e chain: adicionar Destination Address obrigatório.
    • Validação por kind com mensagens acionáveis.
    • Botão Create Swap desabilitado quando faltar campo obrigatório.
  • Arquivos alvo:
    • frontend/src/app/components/xs-wallet/screens/SwapCenter.tsx
    • frontend/src/services/api.ts
    • frontend/src/services/hooks.ts

PR2 - Contrato + Funding/Settlement visíveis

  • Objetivo: mostrar claramente “o que vai acontecer” e “o que o usuário deve fazer agora”.
  • Mudanças:
    • Bloco Resumo do Contrato antes do submit (route, amount, destination, timeout, fees).
    • Após create: painel Funding Details com lockup_address, amount, copy/QR.
    • Para reverse: painel Invoice to Pay com copy e estado.
  • Arquivos alvo:
    • frontend/src/app/components/xs-wallet/screens/SwapCenter.tsx
    • frontend/src/services/hooks.ts

PR3 - Detalhes operacionais por swap

  • Objetivo: tornar o card do swap autossuficiente para operação e suporte.
  • Mudanças:
    • Painel Settlement Details (claim/refund destination, txids, timeout).
    • Timeline expandida com trigger, state transition e details_json.
    • Labels de estado em linguagem operacional (“Aguardando funding”, “Aguardando broadcast do provider”).
  • Arquivos alvo:
    • frontend/src/app/components/xs-wallet/screens/SwapCenter.tsx
    • frontend/src/services/api.ts

PR4 - Wizard e guard rails de produção

  • Objetivo: reduzir erro humano no fluxo real.
  • Mudanças:
    • Wizard em 3 etapas: Route/Amount → Destination → Review/Confirm.
    • Guard rails: amount mínimo, chain mismatch, invoice inválida/expirada.
    • Mensagens de erro orientadas a ação corretiva.
  • Arquivos alvo:
    • frontend/src/app/components/xs-wallet/screens/SwapCenter.tsx
    • frontend/src/services/hooks.ts
    • frontend/src/services/api.ts
